# YAM Ultra 2 双臂数采：30 Hz，双路彩色 640×480

首次使用或迁移请先看[仓库内安装与运行指南](yam_quickstart.md)；
本页保留现场父目录 `scripts/22_flash_yam_collect.sh` 的历史操作记录。
独立克隆本仓库后，对应入口为 `bash scripts/collect_yam.sh`。
最新完整任务与误差结果见[2026-11-25验证报告](validation/2026-11-25-yam.md)。

本入口用于双臂手动示教流程测试。复用已验证的 YAMBackend、
`capture_observation`、共享相机缓存、DistributedRecorder 和原生 episode 发布。
不加载旧轨迹，不改电机零位，不增加额外重力力矩。

## 当前设置

- 左右机械臂：`can_left` / `can_right`，YAM Ultra 2 + linear_4310。
- 相机：两台 D405，左 USB `1-5.3`、右 USB `1-5.4`，使用稳定 by-path 彩色节点。
- 相机原生彩色：640×480，30 FPS，YUYV 解码为既有 BGR 管线格式。
  没有深度流，也没有 overhead 相机；不把两路伪装成三路。
- 状态/示教标签：30 Hz，14维，`[left q1..q6, left gripper, right q1..q6, right gripper]`。
  关节为 rad，夹爪归一化 `0=闭合、1=张开`；qvel 为对应坐标每秒变化量。
- 示教动作标签为同一行测得的绝对 qpos，元数据声明
  `action_label_source=same_row_measured_qpos`，不是发给电机的力矩命令。
- 控制器的内部频率不改成30Hz；30Hz指采样/示教标签频率。
- 相机服务器负责 libx264 编码；帧编号、驱动单调时间戳和消费者时间戳完整保留。
  采样帧缺失、过期或偏斜时仍按原契约退出，不伪造时间戳或补帧。
- 此YAM入口通过原生 `CAMERA_MAX_AGE_MS` 配置帧龄上限为80ms（调用者设置优先）。
  当前两台D405在USB2链路上，图像可用时已有约30ms帧龄，再加30Hz异步采样的等待，
  实测所选帧最大约64.6ms；共享代码默认50ms会拒绝这些帧。
  跨相机时间差仍默认50ms，未来时间戳容差5ms。启动打印限值，元数据与对齐报告保存限值。
  **80ms是本轮采集工程配置，不代表策略已验证可接受该延迟，也不等于满足50ms要求。**
  后续推理应明确采用同一时序配置，或降低延迟并重新验证；不关闭校验。

本轮使用 i2rt 已有环境，加装采集所需的轻量依赖；不依赖训练栈。
补充依赖固定在 `scripts/requirements-yam-capture.txt`。
相机模式保存在 `calibration/d405_640x480_30.npz`，仅含身份和模式，无通用USB摄像头控制预设。

### 本机双路软件编码设置（2026-11-25）

原 `robologger==0.1.7` 写死 `fast` 预设，每路 x264 自动使用12线程。
现场出现录像写入约11–12FPS、128帧队列满、丢帧及录制状态心跳超时。
相机服务器现在为 `libx264` 配置 `ultrafast`、1个编码线程、1个颜色转换线程、`zerolatency`；
保持H.264、yuv420p、5Mbps、原始分辨率/FPS及原有帧引用和时间戳契约。
更快预设可能降低同码率下的压缩画质，不等于完成图像质量或严格同步验收。

所用依赖增加四个可选相机配置字段，未配置时保持上游行为。
已安装环境已应用补丁；重装 `robologger==0.1.7` 后，从本仓库根目录执行：

```bash
../i2rt/.venv/bin/python scripts/apply_yam_robologger_patch.py
```

补丁保存在本仓库 `scripts/patches/robologger-0.1.7-encoder-options.patch`。
恢复上游依赖可用patch工具反向应用该补丁，并移除相机服务器的 `encoder_*` 和 `filter_threads` 配置字段。
实际生效的编码参数以每次原始会话的 `video_*_ffmpeg_attempt1.log` 为准。
现有USB2连接下的流程测试使用调用时显式设置：

```bash
CAMERA_MAX_AGE_MS=150 CAMERA_MAX_SKEW_MS=100 bash scripts/22_flash_yam_collect.sh --camera-only --duration 60
```

这是临时流程测试限值，不替代默认80/50ms下的验收；心跳和缺帧校验保持启用。

同时优化状态写盘：协调进程每轮最多取8条已排队样本，逐条校验后合并写入Zarr，
避免每条样本对二十多个数组分别重复扩容、压缩和写元数据。
不等待凑满批次；逐行保存原始顺序、状态、动作、帧编号和时间戳。
提交计数在实际写盘后更新，暂停/停止仍等待生产者声明的全部样本提交完成。
这也缩短了连续写盘后才能检查心跳的间隔；没有增加队列容量或心跳超时。

## 1. 先验证双路相机录制

从父项目目录运行：

```bash
bash scripts/22_flash_yam_collect.sh --camera-only --duration 10
```

不连接 CAN、不创建机器人。启动两个相机服务器，确认实际帧尺寸，
记录10秒彩色流与原始帧引用，然后关闭本次启动的服务器。
不替换已有相机服务。输出日志含两张开场预览，供检查左右身份和视角。
入口先等待两台服务器发布与共享内存匹配的时钟声明（最多20秒），
再启动帧读取，避免共享内存已创建、声明尚未写入时的启动竞争。
这只用于启动阶段，录制期间的时间戳与帧有效性检查保持不变。

输出位于 Flash 的 `logs/yam_capture/<时间>/` 和
`data/yam_camera_check_30hz/data/<会话>/`，遵循 `config.paths` 环境变量。
检查 `rate.json` 的实际采样频率、相机日志实际FPS、`manifest.json` 完整性、
`alignment_report.json` 帧引用完整性，再进入下一步。
设置30Hz不等于测得30Hz，现场带宽/曝光/编码效果以记录为准。

2026-11-24相机检查 `20261124-230057-2da028`：10秒300条观测，
实测29.999975Hz，间隔P95为33.434ms；两路640×480视频各347帧（含启动/停止阶段），
驱动帧率约30.029Hz，驱动序号无丢帧。原生对齐检查通过，全部300条引用均可解析；
每路引用293张不同图像，异步采样存在重复引用，不强制一条观测对应一张新图。
最大所选帧龄左64.093ms/右64.561ms，最大双相机时间差28.103ms。
两路预览已检查，能看到桌面和夹爪；画面偏青、部分区域偏亮，后续可统一调整成像设置。
这仅验证相机与录制链路，双臂同时采集尚待现场运行。

## 2. 双臂短录制

相机检查通过后，两臂上电，托稳，给夹爪启动标定留出空间。运行：

```bash
bash scripts/22_flash_yam_collect.sh --duration 10
```

1. 输入 `YAM_CAPTURE_READY`。先检查相机，再初始化双臂（夹爪会标定）。
2. 进入重力补偿，手动摆到舒适姿态，按 `1` 开始录制。
3. 缓慢移动双臂和夹爪；10秒后自动停止，也可按 `1` 提前停止。
4. 停止后双臂保持当前位置。按 `1` 保存或 `h` 丢弃。
5. **作出选择后，双臂会返回本次启动姿态，再禁用。保持工作区畅通并托稳。**

录制前 `q` 退出也会返回启动姿态。异常或 Ctrl+C 沿用 YAM 的 safe-exit：
先尝试重力支撑/阻尼，按 `h` 返回启动姿态后关闭；阻尼阶段再次 Ctrl+C 会原地禁用，需托稳。
不可用的驱动不能保证保留支撑。

保存位置：`data/yam_bimanual_30hz/episode_*.zarr`；底层视频和控制数据在
同目录的 `data/<会话>/`。保留整个数据集目录，episode引用原始流，不复制或重新编码视频。
训练task配置与模型训练不在这次流程测试中，不能用默认ARX任务解释YAM坐标。

首条双臂验收：`episode_00000.zarr`（原始会话`20261124-231135-ce12fb`），
300条、29.987518Hz，状态/速度/动作均为14维且有限，两臂均有实际运动；
两路640×480视频完整可解码，帧引用及80ms预算下的对齐检查通过。
左相机300条引用270张不同图像，右300张，保留异步采样的实际引用。
本条夹爪基本保持全开，开合示教尚待补测。录制前后仍出现被拒绝的坏帧，
短次通过不代表连接长期稳定。

## 3. 双臂 pick-and-place 示教（独立夹爪按键）

```bash
bash scripts/22_flash_yam_collect.sh --pick-place --duration 60
```

这是手动引导机械臂、按键控制夹爪的任务示教。先完成左侧抓放，再完成右侧抓放，
两路状态和视频始终共同录制。准备两个轻小物体（例如空塑料杯/泡沫块），
左右工作区分开，目标位置距起点约10cm，首次只抬离桌面几厘米。

初始化和开始/保存仍按原流程：输入YAM_CAPTURE_READY，初始化后按1开始。
看到Recording后以下按键才生效，无需回车：

| 按键 | 操作 |
| --- | --- |
| a | 左夹爪合拢并保持 |
| s | 左夹爪张开 |
| k | 右夹爪合拢并保持 |
| l | 右夹爪张开 |
| 1 | 提前结束录制 |

每侧步骤：手动引导夹爪对准物体 → 手指离开夹持间隙后按闭合键 →
确认物体已夹稳再低位抬起 → 移到目标并落桌 → 按打开键释放。
按键只表示发出位置请求，不代表已检测到夹稳；5N是沿用的SDK限力配置，
不保证每种物体都能抓住。夹爪主动保持时不要手掰，应按对应打开键。
可用一只手引导当前机械臂、另一只手操作附近键盘；另一臂保持在已验证可支撑的姿态。

60秒内完成两个物体的落桌与释放，提前完成可按1结束。到时按原行为保持机械臂和夹爪，
保存/丢弃后仍回启动姿态再禁用；不要带着悬空物体确认回位。
本模式只增加显式的示教夹爪命令：六个臂关节Kp保持0，沿用重力补偿/阻尼，
夹爪使用与SDK限力器匹配的原生增益和既有5N限力设置。
不加此选项时仍为原先全手动示教。数据继续使用同一观测的实测qpos作为动作标签，
元数据标记task_name=bimanual_pick_place、teaching_gripper_control=keyboard_position。
此模式尚待实机验收，不等于已验证自主抓取或轨迹回放。

## 4. 本轮双臂完整任务录制后回放（全手动示教）

用户当前选择完整抓取、搬运、放置测试，包含任务需要的前伸范围，不限定空夹爪或小范围。
运行 `bash scripts/22_flash_yam_collect.sh --duration 60`，不加`--pick-place`；录制时手动控制夹爪，回放时夹爪主动执行记录的归一化开度，沿用YAM后端5N限力。该限力不保证物体一定夹稳。

- 两臂上电并托稳，启动时夹爪留空以完成校准，输入YAM_CAPTURE_READY。
- 将物体放在任务起点，双臂引导至准备姿态，按1开始。完成完整抓放后将物体放稳并释放，双臂回到方便返回起点的准备区域；按1提前结束，或60秒自动结束。
- 录制停止后原始数据已经落盘，两臂保持。提示`1=save, h=discard, r=prepare replay`。这时先不要按1，否则保存后会回启动位并退出。
- 复原物体起始位置，确认回起点路径没有物体/手阻挡后按r：两臂和夹爪立即主动返回录制第一帧。返回动作不是沿录制轨迹倒放，没有碰撞规划。
- 到第一帧后显示左腕相机首帧与当前画面叠加；按1开始双臂30Hz回放，h取消本次回放。单腕叠加不能代替右侧物体/工作区的人工复位。
- 回放中按1停止进入阻尼，再按h按原生流程继续处理；右臂已知大幅前伸重力支撑不足，阻尼不保证悬停，应准备接住。Ctrl+C走既有异常退出流程；回位前先妥善放置物体。
- 回放完成后保持最终姿态，重新出现保存菜单；1保存并回启动姿态/禁用，h丢弃并退出，r可再次回放。退出禁用前托稳。

只回放本轮刚完成的原始数据，不查找旧轨迹。复用load_replay_episode与replay_take；检查完整性、对齐、型号/左右臂角色、30Hz、全部14维动作有限性及夹爪范围后再运动。动作和视频来自原始精确引用，回放不追加到原示教。相机预览通过capture_observation，未改时序预算。
回放使用原生YAM增益（倍率1/1），原有逐行调度、夹爪转换、watchdog、回位和异常退出不变。目标和实测角度保存在`flash-aloha_YAM/logs/replay/`，这是跟踪诊断，不是另录一条带视频的回放episode。原始示教在最终保存后发布；回放异常时原始文件仍保留，但不能声称已发布成功。

本入口的56项模拟/文件测试通过，覆盖原始数据读取、标准采集、YAM后端、回放开始/取消/停止/异常传播及非法数据运动前拒绝。完整任务实机回放尚待用户执行。通用ARX录制/回放测试受当前环境缺少getkey影响未运行通过；本入口不导入该ARX采集器。
